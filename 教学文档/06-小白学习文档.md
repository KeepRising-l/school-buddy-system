## 第1章 项目全景：这个系统做了什么？

### 1.1 一句话描述

这是一个让大学生找到兴趣伙伴的系统。比如你想打篮球但一个人没意思，就在系统上发一个"篮球组局"，别人看到后可以报名参加。

### 1.2 用户能做什么？

| 角色 | 能做什么 |
|------|---------|
| 普通用户 | 注册登录、发布组局、报名参加、评论、评价搭子、设置兴趣标签 |
| 管理员 | 审核帖子、管理用户、管理标签、查看数据统计 |

### 1.3 核心业务流程

```
发布组局 → 别人报名 → 发布者审批(通过/拒绝) → 活动进行 → 标记出勤 → 互相评价
```

这是整个系统最重要的流程，理解了这个，就理解了 70% 的代码。

### 1.4 信誉分机制

每个用户初始 100 分信誉分，行为会影响分数：

| 行为 | 分数变化 |
|------|---------|
| 活动未到场(NOSHOW) | -10 分 |
| 活动开始前1小时内取消报名 | -5 分 |
| 被评价为低分 | 按比例扣分 |

信誉分低于 60 分显示"失信用户"标识，低于 40 分不能发布和报名。

### 3.3 一个请求的完整路径

当用户访问 `GET /api/user/profile` 时：

```

2. UserController        → 接收请求，调用Service
3. UserServiceImpl       → 执行业务逻辑，调用Mapper
4. UserMapper            → 执行SQL查询数据库
5. 数据原路返回           → Entity → Service → Controller → R.ok(data) → 前端
```

这就是经典的**三层架构**：Controller → Service → Mapper。

## 第4章 后端核心：请求怎么处理的？

### 4.1 统一返回 R<T>

所有接口都返回统一格式，这是前后端协作的基础：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}
```

对应后端代码 `R.java`：

```java
public class R<T> {
    private int code;
    private String message;
    private T data;

    // 成功返回
    public static <T> R<T> ok(T data) {
        R<T> r = new R<>();
        r.code = 200;
        r.message = "操作成功";
        r.data = data;
        return r;
    }

    // 失败返回
    public static <T> R<T> fail(ResultCode resultCode) {
        R<T> r = new R<>();
        r.code = resultCode.getCode();
        r.message = resultCode.getMessage();
        return r;
    }
}
```

**为什么这样做？** 前端只需要判断 `code === 200` 就知道成功还是失败，不用每个接口单独处理。

### 4.2 全局异常处理

后端抛出 `BusinessException` 时，全局异常处理器会自动捕获并返回统一格式：

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public R<Void> handleBusinessException(BusinessException e) {
        return R.fail(e.getCode(), e.getMessage());
    }
}
```

**好处：** Service 层只需要 `throw new BusinessException("帖子不存在")`，不用每个方法都写 try-catch。

### 4.3 UserContext（ThreadLocal）

```java
public class UserContext {
    private static final ThreadLocal<Long> THREAD_LOCAL = new ThreadLocal<>();

    public static void setUserId(Long userId) {
        THREAD_LOCAL.set(userId);
    }

    public static Long getUserId() {
        return THREAD_LOCAL.get();
    }

    public static void clear() {
        THREAD_LOCAL.remove();
    }
}
```

**作用：** 在拦截器中解析Token得到userId后，存入ThreadLocal，后续任何地方都能通过 `UserContext.getUserId()` 获取当前登录用户ID，不用一层层传参。

**为什么用ThreadLocal？** 因为服务器同时处理多个请求，每个请求是不同线程，ThreadLocal保证每个线程取到的是自己的userId，不会串。

### 4.4 JWT认证流程

```
1. 用户登录 → 后端验证密码 → 生成JWT Token返回给前端
2. 前端把Token存到localStorage，以后每次请求都带上（Authorization: Bearer xxx）
3. 后端JwtInterceptor拦截请求 → 解析Token → 取出userId → 存入UserContext
4. Controller中通过UserContext.getUserId()获取当前用户
```

核心代码 `JwtInterceptor.java`：

```java
public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
    // 1. 从请求头取Token
    String token = request.getHeader("Authorization");
    if (token == null || !token.startsWith("Bearer ")) {
        response.setStatus(401);
        return false;
    }

    // 2. 解析Token得到userId
    token = token.substring(7);
    Long userId = jwtUtils.getUserIdFromToken(token);

    // 3. 存入UserContext
    UserContext.setUserId(userId);

    // 4. 管理端接口额外校验isAdmin
    if (handler instanceof HandlerMethod) {
        RequireAdmin requireAdmin = ((HandlerMethod) handler).getMethodAnnotation(RequireAdmin.class);
        if (requireAdmin != null) {
            User user = userMapper.selectById(userId);
            if (user == null || user.getIsAdmin() != 1) {
                response.setStatus(403);
                return false;
            }
        }
    }
    return true;
}
```

### 5.3 帖子状态流转

```
RECRUITING（招募中）
    ↓ 人满
FULL（已满员）
    ↓ 活动开始
ONGOING（进行中）
    ↓ 活动结束
FINISHED（已结束）

任何状态 → CANCELLED（已取消）[发布者或管理员操作]
```

对应代码 `PostStateMachine.java`：

```java
public class PostStateMachine {
    // 允许的状态转换
    private static final Map<String, Set<String>> TRANSITIONS = Map.of(
        "RECRUITING", Set.of("FULL", "CANCELLED"),
        "FULL",       Set.of("RECRUITING", "ONGOING", "CANCELLED"),
        "ONGOING",    Set.of("FINISHED", "CANCELLED")
    );

    public static void checkTransition(String from, String to) {
        Set<String> allowed = TRANSITIONS.get(from);
        if (allowed == null || !allowed.contains(to)) {
            throw new BusinessException("帖子状态不允许从" + from + "转为" + to);
        }
    }
}
```

**理解方式：** 这就是一个 Map + if-else，没什么高深的。key 是当前状态，value 是可以转换到哪些状态。

## 第6章 认证模块：登录注册怎么实现的？

### 6.1 注册流程

```
前端：填写学号/手机号 + 密码 + 姓名
  ↓ POST /api/auth/register
后端AuthController.register()
  ↓
UserServiceImpl.register()
  ├── 校验学号/手机号是否已存在
  ├── BCrypt加密密码
  ├── 设置初始信誉分100
  └── 插入user表
```

关键代码：

```java
public void register(RegisterRequest request) {
    // 判断注册方式
    if ("student".equals(request.getRegisterType())) {
        // 学号注册：学号必填
        if (userMapper.selectByStudentNo(request.getStudentNo()) != null) {
            throw new BusinessException("学号已注册");
        }
    } else {
        // 手机号注册：手机号必填
        if (userMapper.selectByPhone(request.getPhone()) != null) {
            throw new BusinessException("手机号已注册");
        }
    }

    User user = new User();
    user.setStudentNo(request.getStudentNo());
    user.setPhone(request.getPhone());
    user.setPassword(BCrypt.hashpw(request.getPassword(), BCrypt.gensalt())); // 加密
    user.setRealName(request.getRealName());
    user.setCreditScore(100); // 初始100分
    userMapper.insert(user);
}
```

### 6.2 登录流程

```
前端：填写账号 + 密码
  ↓ POST /api/auth/login
后端AuthController.login()
  ↓
UserServiceImpl.login()
  ├── 检查Redis是否被锁定（5次失败锁30分钟）
  ├── 查询用户（按学号或手机号）
  ├── BCrypt校验密码
  ├── 密码正确：清除失败计数，生成JWT Token
  └── 密码错误：Redis计数+1，达到5次则锁定30分钟
```

Redis锁定逻辑：

```java
String failKey = "login:fail:" + account;
String failCount = redisTemplate.opsForValue().get(failKey);

if (failCount != null && Integer.parseInt(failCount) >= 5) {
    throw new BusinessException("登录失败次数过多，请30分钟后再试");
}

// 密码错误时
Long count = redisTemplate.opsForValue().increment(failKey); // 计数+1
if (count == 1) {
    redisTemplate.expire(failKey, 30, TimeUnit.MINUTES); // 首次设置30分钟过期
}

// 密码正确时
redisTemplate.delete(failKey); // 清除计数
```

### 7.2 广场列表（推荐排序）

```

  ↓ GET /api/square/list?page=1&size=10&category=球类&sort=recommend
```

推荐算法核心：

```java
private double calculateScore(Post post, Long userId, Set<Long> userTagIds) {
    // 1. 标签匹配度（0-1）
    double tagScore = 0.4;
    if (!userTagIds.isEmpty()) {
        Set<Long> postTagIds = parseTagIds(post.getTagIds());
        long matchCount = postTagIds.stream().filter(userTagIds::contains).count();
        tagScore = 0.4 * ((double) matchCount / userTagIds.size());
    }

    // 2. 时间重合度（越近越高）
    double timeScore = 0.3 * Math.max(0, 1 - hoursUntilStart / 168.0);

    // 3. 信誉分
    double creditScore = 0.2 * (publisher.getCreditScore() / 100.0);

    // 4. 热度（浏览量归一化）
    double hotScore = 0.1 * Math.min(1.0, post.getViewCount() / 100.0);

    return tagScore + timeScore + creditScore + hotScore;
}
```

## 第8章 报名模块：报名→审批→出勤

### 8.1 报名参加

```
前端：点击"报名参加"按钮
  ↓ POST /api/apply/join  {postId}
ApplyServiceImpl.apply()
  ├── 校验帖子存在且状态为RECRUITING
  ├── 校验不能报名自己发布的帖子
  ├── 校验未重复报名
  ├── 校验信誉分（低于40分不能报名）
  ├── 校验段位要求（如果帖子有要求）
  ├── 校验性别要求（如果帖子有要求）
  └── 插入报名记录，状态PENDING
```

### 8.2 审批报名

```
发布者点击"通过"或"拒绝"
  ↓ POST /api/apply/approve/{id}  或  POST /api/apply/reject/{id}
ApplyServiceImpl.approve()
  ├── 校验是帖子发布者
  ├── 校验报名状态为PENDING
  ├── 更新状态为APPROVED
  ├── currentPeople + 1
  └── 如果达到maxPeople，帖子状态改为FULL
```

### 8.3 取消报名

```
报名者点击"取消报名"
  ↓ POST /api/apply/cancel/{id}
ApplyServiceImpl.cancelApply()
  ├── 校验是报名者本人
  ├── 校验状态可取消（PENDING或APPROVED）
  ├── 更新状态为CANCELLED
  ├── 如果帖子是FULL，回退为RECRUITING
  ├── 如果是APPROVED状态取消，currentPeople - 1
  └── 如果活动开始前1小时内取消，扣信誉分5分
```

### 8.4 标记出勤（P0核心功能）

```
发布者点击"已出勤"或"未到场"
  ↓ POST /api/apply/attendance/{id}  {attended: true/false}
ApplyServiceImpl.markAttendance()
  ├── 校验是帖子发布者
  ├── 校验帖子状态为ONGOING或FINISHED
  ├── 校验报名状态为APPROVED
  ├── 更新状态为ATTENDED或NOSHOW
  └── 如果NOSHOW，扣信誉分10分
```

### 8.5 报名状态完整流转

```
PENDING（待审核）
  ↓ 通过
APPROVED（已通过）
  ↓ 标记出勤          ↓ 标记未到场
ATTENDED（已出勤）   NOSHOW（未到场，扣10分）

PENDING → REJECTED（已拒绝）
PENDING/APPROVED → CANCELLED（已取消，可能扣5分）
```

## 第10章 推荐算法：广场页怎么排序的？

### 10.1 算法公式

```
推荐分数 = 0.4 × 标签匹配度 + 0.3 × 时间重合度 + 0.2 × 信誉分 + 0.1 × 热度
```

### 10.2 各因子含义

| 因子 | 权重 | 含义 | 怎么算的 |
|------|------|------|---------|
| 标签匹配 | 0.4 | 帖子标签和你的兴趣标签重合越多分越高 | 重合数/你的标签总数 |
| 时间重合 | 0.3 | 活动越近分越高 | 1 - 距离开始的小时数/168 |
| 信誉分 | 0.2 | 发布者信誉越高分越高 | 信誉分/100 |
| 热度 | 0.1 | 浏览量越多分越高 | min(1, 浏览量/100) |

### 10.3 排序方式

前端可以选择三种排序：
- **推荐**：按上述算法排序
- **最新**：按发布时间倒序
- **最热**：按浏览量倒序

### 10.4 筛选条件

- **分类筛选**：球类、电竞、桌游等
- **时间筛选**：今天、本周、本月
- **关键词搜索**：搜索标题、地点、描述

## 第11章 管理端：后台管理怎么做的？

### 11.1 管理端鉴权

管理端所有接口都加了 `@RequireAdmin` 注解：

```java
@RestController
@RequestMapping("/api/admin/user")
public class AdminUserController {

    @RequireAdmin
    @GetMapping("/list")
    public R<IPage<UserVO>> getUserList(...) { ... }
}
```

JwtInterceptor 检测到 `@RequireAdmin` 注解时，会额外校验 `user.getIsAdmin() == 1`，非管理员返回 403。

### 12.2 请求封装

`request.js` 做了两件事：
1. **请求拦截**：自动加Token到请求头
2. **响应拦截**：统一处理错误码（401跳登录、其他显示错误提示）

```javascript
// 请求拦截器
request.interceptors.request.use(config => {
    const token = localStorage.getItem('h5_token')
    if (token) {
        config.headers.Authorization = `Bearer ${token}`
    }
    return config
})

// 响应拦截器
request.interceptors.response.use(response => {
    const res = response.data
    if (res.code === 200) return res       // 成功
    showToast(res.message)                  // 失败提示
    if (res.code === 401) {                 // Token过期
        router.push('/login')
    }
    return Promise.reject(res.message)
})
```

## 第13章 前后端联调：接口怎么对接的？

### 13.1 对接规则

1. **URL对应**：前端API文件的URL和后端Controller的@RequestMapping一致
2. **参数对应**：前端传的参数名和后端DTO字段名一致
3. **返回对应**：后端返回的字段名和前端使用的字段名一致

### 13.2 举例：登录接口

**后端**：
```java
@PostMapping("/api/auth/login")
public R<Map<String, Object>> login(@RequestBody LoginRequest request) {
    // request包含：account, password
    // 返回：{token: "xxx", user: {id, nickname, ...}}
}
```

**前端**：
```javascript
export const login = (data) => request.post('/api/auth/login', data)
// data = {account: 'xxx', password: 'xxx'}
// 返回 res.data = {token: "xxx", user: {id, nickname, ...}}
```

### 13.3 常见联调问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 403 Forbidden | H5调用了admin接口 | 用用户端公开接口 |
| 字段不显示 | 后端VO没有该字段 | VO添加字段并填充 |
| 参数提交400 | 前端字段名和后端不一致 | 统一字段名 |
| 401 Unauthorized | Token过期或未传 | 重新登录 |

### 13.4 VO vs Entity

- **Entity**：直接对应数据库表，包含所有字段（包括密码等敏感信息）
- **VO**：返回给前端的数据，只包含需要展示的字段

**永远不要直接返回Entity给前端！** 比如User实体包含password字段，直接返回会泄露密码。

## 第14章 常见问题FAQ

### Q1：怎么启动项目？

```bash
# 1. 启动MySQL，创建数据库
CREATE DATABASE buddy DEFAULT CHARSET utf8mb4;

# 2. 启动Redis
redis-server

# 4. 启动H5前端
cd frontend-h5
npm run dev

# 5. 启动管理端前端
cd frontend-admin
npm run dev
```

### Q2：怎么创建管理员账号？

在数据库中手动更新：
```sql
UPDATE user SET is_admin = 1 WHERE id = 1;
```

### Q3：怎么调试接口？

使用 Postman 或 Apifox：
1. 先调用登录接口获取Token
2. 其他接口在Header中加 `Authorization: Bearer <Token>`
3. 管理端接口需要管理员Token

### Q4：帖子状态什么时候自动变化？

本项目帖子状态**不会自动变化**，需要手动触发：
- 人满时：审批报名通过后自动变为FULL
- 活动开始/结束：需要管理员或发布者手动操作
- 下架：管理员或发布者手动取消

### Q5：推荐算法什么时候生效？

每次请求广场列表时实时计算，结果缓存5分钟（Redis）。

### Q6：信誉分什么时候变化？

| 场景 | 变化 |
|------|------|
| 被标记NOSHOW | -10分 |
| 活动前1小时内取消报名 | -5分 |
| 被评价1星 | -4分 |
| 被评价5星 | +2分 |
| 被管理员重置 | 设为指定值 |

### Q7：为什么用ThreadLocal而不是直接传userId？

因为每个Controller方法都需要userId，如果作为参数传递，每个方法都要加一个参数，代码冗余。用ThreadLocal在拦截器中设置一次，后续任何地方都能获取。

### Q8：MyBatis-Plus的LambdaQueryWrapper怎么理解？

```java
// 等价于 SQL: SELECT * FROM post WHERE status = 'RECRUITING' AND category = '球类'
new LambdaQueryWrapper<Post>()
    .eq(Post::getStatus, "RECRUITING")
    .eq(Post::getCategory, "球类")
```

`Post::getStatus` 是方法引用，MyBatis-Plus会自动推导出字段名 `status`，避免硬编码字符串。

### Q9：前端怎么知道用户是发布者还是报名者？

帖子详情接口返回 `publisherId`，前端对比：

```javascript
const isOwner = computed(() => {
    return post.value?.publisherId === userStore.userInfo?.id
})
```

### Q10：怎么扩展新功能？

按照以下步骤：
1. 建表 → 写Entity
2. 写Mapper接口（继承BaseMapper）
3. 写Service接口 + ServiceImpl
4. 写Controller
5. 前端写API调用
6. 前端写页面
