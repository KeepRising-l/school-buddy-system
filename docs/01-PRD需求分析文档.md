## 一、项目背景

### 1.1 现状与痛点

在高校校园中，学生群体存在大量"找搭子"的隐性需求：

- **运动场景**：想打篮球/羽毛球，但宿舍室友不感兴趣，凑不齐人；
- **电竞场景**：想上分，但路人队友不靠谱，希望找到段位相近的同学；
- **桌游场景**：剧本杀、狼人杀需要固定人数，缺人就无法开局；
- **跑步场景**：一个人跑步缺乏动力，希望找到配速相近的伙伴。

目前学生解决这类需求的方式主要是：

1. 在班级群/社团群发消息——**覆盖面窄，容易刷屏，信息很快被淹没**；
2. 在表白墙/校园论坛发帖——**信息杂乱，无法按兴趣筛选，无法完成预约闭环**；
3. 线下随机约——**效率低，且无法了解对方水平，体验差**。

### 1.2 项目定位

构建一个**面向高校学生的兴趣搭子预约平台**，通过"标签化匹配 + 状态化预约 + 信用化评价"三位一体的机制，解决校园找搭子难、约搭子难、搭子不靠谱三大痛点。

### 1.3 项目目标

| 目标层级 | 目标内容 | 衡量指标 |
|---------|---------|---------|
| 核心目标 | 让学生能快速找到兴趣相投、水平相近的搭子 | 发帖到满员平均时长 < 24h |
| 业务目标 | 完成从"发帖→报名→活动→评价"的完整闭环 | 组局成功率 > 60% |
| 安全目标 | 通过身份审核和信誉机制保障校园社交安全 | 违规用户封禁响应 < 4h |
| 体验目标 | H5 轻量访问，无需下载 App 即可使用 | 首屏加载 < 2s |

## 二、名词解释

| 术语 | 含义 |
|------|------|
| 搭子 | 一起参与某项活动的伙伴（如球搭子、游戏搭子） |
| 组局/帖子 | 发起人创建的一个活动招募帖，包含时间、地点、人数等信息 |
| 广场 | 所有正在进行中组局帖子的聚合列表页 |
| 段位 | 用户在某项兴趣上的自评水平，分为青铜、白银、黄金、钻石、王者五级 |
| 信誉分 | 基于历史互评计算的用户信用分数，满分 100 分 |
| 履约 | 用户按约定参加活动，未爽约、未迟到 |
| 沉底 | 信誉分过低的用户发布的帖子在广场列表中被降权排序 |

## 五、详细需求

### 5.1 用户模块

#### 5.1.1 注册登录

**功能描述**：支持学生通过学号或手机号注册账号，并使用密码登录。

**业务规则**：

| 规则编号 | 规则内容 |
|---------|---------|
| REG-01 | 学号注册时需填写：学号、密码、确认密码、姓名（真实姓名，用于审核） |
| REG-02 | 手机号注册时需填写：手机号、密码、确认密码、姓名 |
| REG-03 | 学号格式校验：8-12 位数字 |
| REG-04 | 手机号格式校验：11 位数字，符合国内手机号规则 |
| REG-05 | 密码强度：8-20 位，至少包含字母和数字 |
| REG-06 | 学号、手机号均不可重复注册 |
| REG-07 | 注册成功后默认信誉分为 100 分 |
| REG-08 | 登录支持学号或手机号 + 密码方式 |
| REG-09 | 登录成功后返回 JWT Token，有效期 7 天 |
| REG-10 | 连续登录失败 5 次锁定账号 30 分钟 |

**界面要素**（H5）：

- 注册页：输入框（学号/手机号切换 Tab）、密码框、确认密码框、姓名框、注册按钮
- 登录页：账号输入框、密码输入框、登录按钮、去注册链接

#### 5.1.2 个人资料

**功能描述**：用户可编辑自己的个人资料信息。

**可编辑字段**：

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|---------|
| 昵称 | 文本 | 是 | 2-20 字符，不可包含特殊符号 |
| 头像 | 图片 | 否 | 支持 jpg/png，大小 < 2MB，默认头像 |
| 个性签名 | 文本 | 否 | 最长 100 字符 |
| 所属学院 | 下拉选择 | 是 | 预设学院列表 |
| 性别 | 单选 | 否 | 男/女/保密 |

**不可编辑字段**：学号、信誉分、注册时间。

#### 5.1.3 兴趣标签设置

**功能描述**：用户选择自己感兴趣的运动/游戏类别，并设置自己在每个项目上的水平段位。

**业务规则**：

| 规则编号 | 规则内容 |
|---------|---------|
| TAG-01 | 用户可从系统预设的兴趣标签中选择多个（至少 1 个，最多 10 个） |
| TAG-02 | 每个选中的标签需设置自评段位：青铜(1)、白银(2)、黄金(3)、钻石(4)、王者(5) |
| TAG-03 | 兴趣标签按分类展示：球类、电竞、桌游、跑步等 |
| TAG-04 | 标签设置影响推荐算法的个性化展示权重 |
| TAG-05 | 用户可随时修改自己的标签和段位 |

#### 5.1.4 我的发布

**功能描述**：查看自己发布过的所有组局帖子，按状态分类展示。

**展示规则**：

- 按状态分 Tab 展示：全部 / 招募中 / 进行中 / 已结束
- 每条卡片显示：标题、分类、时间、当前人数/最大人数、状态标签
- 点击卡片进入帖子详情
- 招募中的帖子可查看报名列表，可同意/拒绝报名申请

#### 5.1.5 我的预约

**功能描述**：查看自己报名的组局，以及别人发来的邀请。

**展示规则**：

- 分两个 Tab：我报名的 / 收到的邀请
- "我报名的"展示：已加入的、待审核的、已拒绝的、已结束的
- "收到的邀请"展示：别人报名我发布的帖子的申请列表
- 可对待处理的申请进行同意/拒绝操作

### 5.2 帖子模块

#### 5.2.1 发布组局

**功能描述**：用户填写组局信息，发布一个招募搭子的帖子。

**表单字段**：

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|---------|
| 标题 | 文本 | 是 | 5-30 字符 |
| 兴趣分类 | 下拉选择 | 是 | 从系统标签中选择 |
| 具体项目 | 下拉选择 | 是 | 根据分类联动 |
| 开始时间 | 日期时间 | 是 | 必须晚于当前时间 1 小时 |
| 结束时间 | 日期时间 | 是 | 必须晚于开始时间 |
| 活动地点 | 文本 | 是 | 最长 50 字符 |
| 人数限制 | 数字 | 是 | 2-20 人 |
| 要求段位 | 下拉选择 | 否 | 不限/青铜以上/白银以上/.../王者 |
| 要求性别 | 单选 | 否 | 不限/仅男/仅女 |
| 详细描述 | 富文本 | 否 | 最长 500 字符 |

**业务规则**：

| 规则编号 | 规则内容 |
|---------|---------|
| POST-01 | 信誉分 < 60 的用户无法发布新组局 |
| POST-02 | 发布者默认占用 1 个名额，current_people 初始为 1 |
| POST-03 | 帖子发布后默认状态为"招募中(RECRUITING)" |
| POST-04 | 帖子发布后默认审核状态为"已通过"（可配置为需审核） |
| POST-05 | 同一用户同时进行中的招募帖不超过 5 个 |

#### 5.2.2 帖子列表（广场）

**功能描述**：展示所有正在进行中（招募中 + 已满员）的组局帖子。

**展示规则**：

| 规则编号 | 规则内容 |
|---------|---------|
| SQ-01 | 默认按推荐算法排序展示（见 5.3 智能推荐模块） |
| SQ-02 | 支持按分类筛选：全部/球类/电竞/桌游/跑步 |
| SQ-03 | 支持按时间筛选：今天/本周/本月 |
| SQ-04 | 支持按热度排序（报名人数降序） |
| SQ-05 | 每页加载 10 条，支持下拉加载更多 |
| SQ-06 | 每条卡片展示：标题、分类标签、时间、地点、人数（3/5）、发布者昵称+信誉星级 |
| SQ-07 | 已满员的帖子显示"已满员"标记但仍展示 |
| SQ-08 | 信誉分 < 60 的用户发布的帖子沉底展示 |

#### 5.2.3 帖子详情

**功能描述**：查看组局帖子的完整信息。

**页面内容**：

- **顶部信息区**：标题、状态标签、分类标签
- **活动信息区**：时间、地点、人数（当前/最大）、段位要求、性别要求
- **详细描述**：发布者填写的描述内容
- **发布者信息**：头像、昵称、信誉星级、所属学院、兴趣标签
- **报名情况**：当前已报名人数、已报名用户头像列表
- **操作区**：报名按钮 / 取消报名按钮 / 已满员提示
- **评论区**：展示评论列表，可发表评论

**业务规则**：

| 规则编号 | 规则内容 |
|---------|---------|
| DET-01 | 浏览帖子详情时 view_count + 1（同一用户 10 分钟内只计一次） |
| DET-02 | 帖子发布者进入详情页时显示"管理报名"入口 |
| DET-03 | 已结束的帖子详情页显示"评价"入口 |

#### 5.2.4 报名/取消报名

**功能描述**：用户可申请加入组局，也可取消已报名的活动。

**报名业务规则**：

| 规则编号 | 规则内容 |
|---------|---------|
| APP-01 | 信誉分 < 60 的用户无法报名 |
| APP-02 | 帖子状态必须为 RECRUITING 才可报名 |
| APP-03 | 已满员的帖子不可报名 |
| APP-04 | 不可报名自己发布的帖子 |
| APP-05 | 不可重复报名同一帖子 |
| APP-06 | 若帖子设置了段位要求，用户需满足要求才可报名 |
| APP-07 | 若帖子设置了性别要求，用户需满足要求才可报名 |
| APP-08 | 报名后状态为 PENDING（待审核），需发布者同意 |
| APP-09 | 发布者同意后，报名状态变为 APPROVED，帖子 current_people + 1 |
| APP-10 | current_people 达到 max_people 时，帖子状态自动变为 FULL |

**取消报名业务规则**：

| 规则编号 | 规则内容 |
|---------|---------|
| CAN-01 | 招募中/已满员状态可取消报名 |
| CAN-02 | 取消后 current_people - 1，若帖子为 FULL 状态则回退为 RECRUITING |
| CAN-03 | 活动开始前 1 小时内取消报名，扣除信誉分 5 分 |
| CAN-04 | 已进入进行中状态不可取消 |

#### 5.2.5 帖子状态流转

**状态定义**：

| 状态 | 英文标识 | 说明 |
|------|---------|------|
| 招募中 | RECRUITING | 正在接受报名 |
| 已满员 | FULL | 人数已满，不再接受报名 |
| 进行中 | ONGOING | 活动已开始，未结束 |
| 已结束 | FINISHED | 活动已结束，可评价 |
| 已取消 | CANCELLED | 发布者取消或管理员下架 |

**状态流转规则**：

| 规则编号 | 触发条件 | 原状态 | 目标状态 |
|---------|---------|--------|---------|
| FLOW-01 | current_people = max_people | RECRUITING | FULL |
| FLOW-02 | 有人取消报名导致 current_people < max_people | FULL | RECRUITING |
| FLOW-03 | 到达 start_time（定时任务） | RECRUITING / FULL | ONGOING |
| FLOW-04 | 到达 end_time（定时任务） | ONGOING | FINISHED |
| FLOW-05 | 发布者主动取消 | RECRUITING / FULL | CANCELLED |
| FLOW-06 | 管理员下架 | 任意 | CANCELLED |

### 5.3 智能推荐模块

#### 5.3.1 综合排序算法

**功能描述**：根据多维度因素计算帖子权重，决定广场列表的展示顺序。

**权重计算公式**：

```
总权重 Score = W1 × 标签匹配度 + W2 × 时间重合度 + W3 × 发布者信誉分 + W4 × 热度因子

其中：
- W1 = 0.4（标签匹配度权重，最重要）
- W2 = 0.3（时间重合度权重）
- W3 = 0.2（发布者信誉分权重）
- W4 = 0.1（热度因子权重）
```

**各维度计算方式**：

| 维度 | 计算方式 | 取值范围 |
|------|---------|---------|
| 标签匹配度 | 用户兴趣标签 ∩ 帖子标签的数量 / 帖子标签总数 | 0 ~ 1 |
| 时间重合度 | 1 - (距活动开始的间隔小时数 / 168) | 0 ~ 1（超过 7 天为 0） |
| 发布者信誉分 | 信誉分 / 100 | 0 ~ 1 |
| 热度因子 | current_people / max_people | 0 ~ 1 |

**业务规则**：

| 规则编号 | 规则内容 |
|---------|---------|
| REC-01 | 游客（未登录）看到的广场按"时间重合度 + 热度因子"排序，不计算标签匹配度 |
| REC-02 | 信誉分 < 60 的用户发布的帖子，Score 乘以 0.3 惩罚系数（沉底） |
| REC-03 | 推荐结果缓存 5 分钟，避免每次请求重复计算 |
| REC-04 | 支持手动切换排序模式：推荐排序 / 最新发布 / 热度排序 |

#### 5.3.2 个性化展示

**功能描述**：根据用户设置的兴趣标签，对广场列表进行个性化微调。

**规则**：

- 用户设置了兴趣标签后，广场顶部增加"你可能感兴趣"横向滚动推荐位（最多 5 条）
- 推荐位展示与用户标签完全匹配的帖子
- 主列表仍按综合排序展示所有帖子

### 5.4 评价与信誉模块

#### 5.4.1 活动互评

**功能描述**：活动结束后，参与双方可互相评价。

**评价规则**：

| 规则编号 | 规则内容 |
|---------|---------|
| REV-01 | 仅 FINISHED 状态的帖子可评价 |
| REV-02 | 仅参与该活动的人（发布者 + 已加入且 ATTENDED 的报名者）可评价 |
| REV-03 | 每对用户在一个帖子中只能互相评价一次 |
| REV-04 | 评价窗口期为活动结束后 7 天，逾期不可评价 |
| REV-05 | 评价包含：星级（1-5 星）、标签（靠谱/爽约/迟到，可多选）、文字评价 |
| REV-06 | 评价提交后不可修改 |

**评价标签与星级映射**：

| 标签 | 建议星级 | 信誉分影响 |
|------|---------|-----------|
| 靠谱 | 5 星 | +2 分 |
| （无负面标签） | 4 星 | +1 分 |
| （中性） | 3 星 | 0 分 |
| 迟到 | 2 星 | -3 分 |
| 爽约 | 1 星 | -10 分 |

#### 5.4.2 信誉分计算

**功能描述**：系统根据用户的历史评价自动计算信誉分。

**计算规则**：

| 规则编号 | 规则内容 |
|---------|---------|
| CRD-01 | 初始信誉分 = 100 |
| CRD-02 | 信誉分 = 100 + 历史所有评价的信誉分影响值之和 |
| CRD-03 | 信誉分最低为 0，最高为 100（超过 100 按 100 计） |
| CRD-04 | 信誉分每日凌晨通过定时任务重新计算并更新 |
| CRD-05 | 爽约（NOSHOW）额外扣 5 分（在评价扣分基础上） |

#### 5.4.3 信誉展示

**展示规则**：

| 位置 | 展示形式 |
|------|---------|
| 个人主页 | 信誉分数字 + 星级（分数/20 向上取整） |
| 帖子卡片 | 星级图标（如 ⭐⭐⭐⭐⭐） |
| 帖子详情-发布者信息 | 信誉分 + 星级 + 评价标签云 |
| 报名列表 | 报名者信誉星级（帮助发布者筛选） |

**星级映射**：

| 信誉分 | 星级 | 标签 |
|--------|------|------|
| 90-100 | 5 星 | 靠谱队友 |
| 75-89 | 4 星 | 优质队友 |
| 60-74 | 3 星 | 普通队友 |
| 40-59 | 2 星 | 需改善 |
| 0-39 | 1 星 | 失信用户 |

#### 5.4.4 失信惩罚

**惩罚规则**：

| 规则编号 | 规则内容 |
|---------|---------|
| PUN-01 | 信誉分 < 60 时，发布的帖子在广场中 Score × 0.3（沉底） |
| PUN-02 | 信誉分 < 60 时，无法发起新组局 |
| PUN-03 | 信誉分 < 60 时，无法报名组局 |
| PUN-04 | 信誉分 < 60 时，个人主页显示"失信用户"警告标识 |
| PUN-05 | 信誉分恢复到 60 及以上时，自动解除所有限制 |

## 七、业务流程

### 7.1 核心业务流程

```
用户注册 → 设置兴趣标签 → 浏览广场（推荐排序）
                                    ↓
                            发布组局 ←──→ 报名组局
                                ↓              ↓
                          管理报名申请    等待审核
                                ↓              ↓
                          同意/拒绝      加入/被拒
                                ↓              ↓
                            满员/到时间 → 进行中
                                              ↓
                                          活动结束
                                              ↓
                                          互相评价
                                              ↓
                                      信誉分更新 → 影响推荐/惩罚
```

### 7.2 帖子生命周期

```
[发布] → RECRUITING（招募中）
              ↓
         人数满 → FULL（已满员）
              ↓
         到开始时间 → ONGOING（进行中）
              ↓
         到结束时间 → FINISHED（已结束）
              ↓
         可评价（7天内）

任何招募中/已满员状态 → 发布者取消/管理员下架 → CANCELLED
```
