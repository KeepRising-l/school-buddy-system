## 六、核心业务逻辑实现

### 6.1 帖子状态机

```
[发布] → RECRUITING ──满员──→ FULL
              ↑                    │
              │取消报名              │到达start_time
              │                    ↓
              └──────────── ONGOING ──到达end_time──→ FINISHED
              
RECRUITING/FULL ──发布者取消/管理员下架──→ CANCELLED
```

### 6.2 推荐算法

```
Score = 0.4 × 标签匹配度 + 0.3 × 时间重合度 + 0.2 × 信誉分/100 + 0.1 × 热度因子

标签匹配度 = 用户标签 ∩ 帖子标签数量 / 帖子标签总数
时间重合度 = 1 - (距活动开始小时数 / 168)，超过7天为0
热度因子   = currentPeople / maxPeople
低信誉惩罚 = 信誉分<60 时 Score × 0.3
```

### 6.3 信誉分体系

```
初始分 = 100
评价影响：靠谱+2, 4星+1, 3星0, 迟到-3, 爽约-10
额外惩罚：爽约NOSHOW额外-5, 临场取消-5
星级映射：90-100→5星靠谱队友, 75-89→4星, 60-74→3星, 40-59→2星, 0-39→1星失信
失信惩罚：<60 禁止发帖+禁止报名+帖子沉底
```

### 6.4 定时任务

| 任务 | 执行频率 | 说明 |
|------|---------|------|
| 帖子状态推进 | 每5分钟 | RECRUITING/FULL→ONGOING, ONGOING→FINISHED |
| 信誉分重算 | 每天凌晨2点 | 重新计算所有用户信誉分 |
