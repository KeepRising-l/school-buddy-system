## 第一步：创建统一返回类 R\<T\>

### 为什么需要统一返回？

前端最怕后端返回格式不统一。比如：

```json
// 有时返回这样
{"code": 0, "msg": "ok", "data": {...}}
// 有时返回这样
{"status": 200, "message": "success", "result": [...]}
// 出错了又变成这样
{"error": "用户不存在"}
```

前端开发者会崩溃的！所以我们需要一个统一的返回格式：

```json
{
  "code": 200,
  "message": "success",
  "data": {...}
}
```

### 创建文件

`src/main/java/com/buddy/common/result/R.java`

### 写入代码

```java
package com.buddy.common.result;

import lombok.Data;

import java.io.Serializable;

/**
 * 统一返回结果类
 * 所有接口都返回这个格式：{code, message, data}
 */
@Data
public class R<T> implements Serializable {

    /** 状态码 */
    private int code;

    /** 提示信息 */
    private String message;

    /** 数据 */
    private T data;

    /**
     * 成功 - 无数据
     * 用法：return R.ok();
     */
    public static <T> R<T> ok() {
        R<T> r = new R<>();
        r.setCode(200);
        r.setMessage("success");
        return r;
    }

    /**
     * 成功 - 带数据
     * 用法：return R.ok(user);
     */
    public static <T> R<T> ok(T data) {
        R<T> r = new R<>();
        r.setCode(200);
        r.setMessage("success");
        r.setData(data);
        return r;
    }

    /**
     * 成功 - 自定义消息和数据
     * 用法：return R.ok("注册成功", user);
     */
    public static <T> R<T> ok(String message, T data) {
        R<T> r = new R<>();
        r.setCode(200);
        r.setMessage(message);
        r.setData(data);
        return r;
    }

    /**
     * 失败 - 仅消息
     * 用法：return R.fail("用户名不能为空");
     */
    public static <T> R<T> fail(String message) {
        R<T> r = new R<>();
        r.setCode(400);
        r.setMessage(message);
        return r;
    }

    /**
     * 失败 - 自定义状态码和消息
     * 用法：return R.fail(401, "未登录");
     */
    public static <T> R<T> fail(int code, String message) {
        R<T> r = new R<>();
        r.setCode(code);
        r.setMessage(message);
        return r;
    }

    /**
     * 失败 - 使用 ResultCode 枚举
     * 用法：return R.fail(ResultCode.USER_NOT_FOUND);
     */
    public static <T> R<T> fail(ResultCode resultCode) {
        R<T> r = new R<>();
        r.setCode(resultCode.getCode());
        r.setMessage(resultCode.getMessage());
        return r;
    }

    /**
     * 未授权快捷方法
     * 用法：return R.unauthorized();
     */
    public static <T> R<T> unauthorized() {
        R<T> r = new R<>();
        r.setCode(401);
        r.setMessage("未登录或Token已过期");
        return r;
    }

    /**
     * 禁止访问快捷方法
     * 用法：return R.forbidden();
     */
    public static <T> R<T> forbidden() {
        R<T> r = new R<>();
        r.setCode(403);
        r.setMessage("无权限访问");
        return r;
    }
}
```

### 解释

- **泛型 `<T>`**：data 字段可以是任何类型——User、List\<Post\>、String 等，用泛型保证类型安全
- **静态工厂方法**：用 `R.ok()` 和 `R.fail()` 而不是 `new R<>()` + `setCode()`，代码更简洁
- **`Serializable`**：实现序列化接口，万一需要存 Redis 或传输时不会报错
- **`unauthorized()` 和 `forbidden()`**：这两个是高频使用的快捷方法，单独提出来避免到处写 `R.fail(401, "...")`

## 第二步：创建 ResultCode 枚举

### 为什么需要枚举？

如果到处写 `R.fail(1001, "用户已存在")`，魔术数字散落在代码各处，很难维护。用枚举集中管理所有错误码，一目了然。

### 创建文件

`src/main/java/com/buddy/common/result/ResultCode.java`

### 写入代码

```java
package com.buddy.common.result;

import lombok.AllArgsConstructor;
import lombok.Getter;

/**
 * 返回码枚举
 * 集中管理所有业务状态码和对应消息
 */
@Getter
@AllArgsConstructor
public enum ResultCode {

    // ========== 通用码 ==========
    SUCCESS(200, "操作成功"),
    BAD_REQUEST(400, "请求参数错误"),
    UNAUTHORIZED(401, "未登录"),
    FORBIDDEN(403, "无权限"),
    NOT_FOUND(404, "资源不存在"),
    SERVER_ERROR(500, "服务器内部错误"),

    // ========== 业务码（1xxx） ==========
    USER_EXISTS(1001, "用户已存在"),
    USER_NOT_FOUND(1002, "用户不存在"),
    PASSWORD_ERROR(1003, "密码错误"),
    CREDIT_TOO_LOW(1004, "信誉分过低，无法操作"),
    POST_NOT_RECRUITING(1005, "帖子不在招募中"),
    APPLY_DUPLICATE(1006, "已报名该活动"),
    APPLY_NOT_QUALIFIED(1007, "不满足报名要求"),
    STATUS_TRANSIT_ERROR(1008, "状态流转不合法"),
    REVIEW_DUPLICATE(1009, "已评价过该用户"),
    REVIEW_WINDOW_EXPIRED(1010, "评价窗口已过期");

    /** 状态码 */
    private final int code;

    /** 提示消息 */
    private final String message;
}
```

### 解释

- **通用码 2xx/4xx/5xx**：遵循 HTTP 状态码语义，200 成功、400 客户端错误、401 未认证、403 无权限、404 找不到、500 服务器错误
- **业务码 1xxx**：自定义的业务错误码，从 1001 开始，和 HTTP 状态码区分开，前端可以根据 code 做不同处理
- **`@Getter`**：Lombok 自动生成 `getCode()` 和 `getMessage()` 方法
- **`@AllArgsConstructor`**：Lombok 自动生成 `new ResultCode(200, "操作成功")` 构造方法

## 第三步：创建 BusinessException

### 为什么需要自定义异常？

Java 自带的 `RuntimeException` 只有一个 message 字段，没有 code。我们的业务异常需要同时携带 code 和 message，这样全局异常处理器才能返回正确的状态码。

### 创建文件

`src/main/java/com/buddy/common/exception/BusinessException.java`

### 写入代码

```java
package com.buddy.common.exception;

import com.buddy.common.result.ResultCode;
import lombok.Getter;

/**
 * 业务异常类
 * 在 Service 层抛出，由 GlobalExceptionHandler 统一捕获并返回给前端
 */
@Getter
public class BusinessException extends RuntimeException {

    /** 错误码 */
    private final int code;

    /**
     * 仅消息（默认 code=400）
     * 用法：throw new BusinessException("用户名不能为空");
     */
    public BusinessException(String message) {
        super(message);
        this.code = 400;
    }

    /**
     * 自定义状态码和消息
     * 用法：throw new BusinessException(401, "Token已过期");
     */
    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
    }

    /**
     * 使用 ResultCode 枚举（推荐）
     * 用法：throw new BusinessException(ResultCode.USER_NOT_FOUND);
     */
    public BusinessException(ResultCode resultCode) {
        super(resultCode.getMessage());
        this.code = resultCode.getCode();
    }

    /**
     * 使用 ResultCode 枚举，但自定义消息
     * 用法：throw new BusinessException(ResultCode.BAD_REQUEST, "手机号格式不正确");
     */
    public BusinessException(ResultCode resultCode, String message) {
        super(message);
        this.code = resultCode.getCode();
    }
}
```

### 解释

- **继承 `RuntimeException`**：这是非受检异常，不需要在方法签名上声明 `throws`，避免代码到处都是 try-catch
- **4 个构造方法**：覆盖不同使用场景，最推荐的是 `throw new BusinessException(ResultCode.XXX)`，语义清晰
- **`@Getter`**：让 GlobalExceptionHandler 可以通过 `getCode()` 获取错误码

**使用示例：**

```java
// 在 Service 层抛出
public User login(String studentNo, String password) {
    User user = userMapper.selectByStudentNo(studentNo);
    if (user == null) {
        throw new BusinessException(ResultCode.USER_NOT_FOUND);
    }
    if (!passwordEncoder.matches(password, user.getPassword())) {
        throw new BusinessException(ResultCode.PASSWORD_ERROR);
    }
    return user;
}
```

## 第四步：创建 GlobalExceptionHandler

### 为什么需要全局异常处理器？

如果没有全局异常处理器，Controller 里每个方法都要 try-catch：

```java
// ❌ 不好的写法
@GetMapping("/user/{id}")
public R<User> getUser(@PathVariable Long id) {
    try {
        User user = userService.getById(id);
        return R.ok(user);
    } catch (BusinessException e) {
        return R.fail(e.getCode(), e.getMessage());
    } catch (Exception e) {
        return R.fail(500, "服务器内部错误");
    }
}
```

有了全局异常处理器，Controller 只管写业务逻辑，异常自动被捕获并转换成统一格式：

```java
// ✅ 好的写法
@GetMapping("/user/{id}")
public R<User> getUser(@PathVariable Long id) {
    return R.ok(userService.getById(id));
}
```

### 创建文件

`src/main/java/com/buddy/common/exception/GlobalExceptionHandler.java`

### 写入代码

```java
package com.buddy.common.exception;

import com.buddy.common.result.R;
import lombok.extern.slf4j.Slf4j;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

import java.util.stream.Collectors;

/**
 * 全局异常处理器
 * 拦截所有 Controller 抛出的异常，统一转换成 R 格式返回给前端
 */
@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    /**
     * 处理业务异常
     * 这是我们主动抛出的异常，需要返回具体的错误码和消息
     */
    @ExceptionHandler(BusinessException.class)
    public R<Void> handleBusinessException(BusinessException e) {
        log.warn("业务异常: code={}, message={}", e.getCode(), e.getMessage());
        return R.fail(e.getCode(), e.getMessage());
    }

    /**
     * 处理参数校验异常
     * 当 @Valid 校验失败时抛出，需要把所有字段的错误信息拼接返回
     */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public R<Void> handleValidationException(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
                .map(FieldError::getDefaultMessage)
                .collect(Collectors.joining("; "));
        log.warn("参数校验失败: {}", message);
        return R.fail(400, message);
    }

    /**
     * 处理其他所有异常
     * 兜底处理，防止未预期的异常导致前端收到非 JSON 响应
     */
    @ExceptionHandler(Exception.class)
    public R<Void> handleException(Exception e) {
        log.error("服务器内部错误", e);
        return R.fail(500, "服务器内部错误");
    }
}
```

### 解释

- **@RestControllerAdvice**：等于 `@ControllerAdvice` + `@ResponseBody`，表示这是一个全局的 Controller 增强类，返回值自动序列化为 JSON
- **@ExceptionHandler(BusinessException.class)**：只捕获 BusinessException，其他异常不会进来
- **MethodArgumentNotValidException**：当使用 `@Valid` 注解校验请求参数失败时抛出，比如 `@NotBlank(message = "学号不能为空")` 校验不通过
- **Exception 兜底**：任何未预期的异常（如 NullPointerException、数据库连接异常等）都会被捕获，返回 500，同时打印完整错误日志方便排查
- **log.warn vs log.error**：业务异常是预期内的，用 warn 级别；未知异常是预期外的，用 error 级别并打印堆栈

## 第五步：创建 MyBatis-Plus 配置类

### 为什么需要配置？

MyBatis-Plus 默认不带分页功能，需要注册分页插件才能使用 `Page` 对象进行分页查询。这是企业项目的标配。

### 创建文件

`src/main/java/com/buddy/config/MybatisPlusConfig.java`

### 写入代码

```java
package com.buddy.config;

import com.baomidou.mybatisplus.annotation.DbType;
import com.baomidou.mybatisplus.extension.plugins.MybatisPlusInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.OptimisticLockerInnerInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.PaginationInnerInterceptor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

/**
 * MyBatis-Plus 配置
 * 注册分页插件和乐观锁插件
 */
@Configuration
public class MybatisPlusConfig {

    /**
     * MyBatis-Plus 拦截器配置
     * 分页插件：让 selectPage 等分页方法生效
     * 乐观锁插件：更新时自动校验版本号，防止并发修改冲突
     */
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 分页插件，指定数据库类型为 MySQL
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        // 乐观锁插件
        interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());
        return interceptor;
    }
}
```

### 解释

- **PaginationInnerInterceptor**：分页插件，不注册的话 `mapper.selectPage()` 返回的是全部数据而不是分页数据。`DbType.MYSQL` 告诉插件生成 MySQL 方言的 `LIMIT` 语句
- **OptimisticLockerInnerInterceptor**：乐观锁插件，当 Entity 有 `@Version` 字段时，更新会自动加 `WHERE version = ?` 条件，防止并发修改丢失

package com.buddy.entity;

import com.baomidou.mybatisplus.annotation.*;
import com.baomidou.mybatisplus.extension.activerecord.Model;

import java.time.LocalDateTime;

/**
 * 用户实体
 * 对应数据库表 sys_user

    /** 状态：1正常 0封禁 */
    private Integer status;

    /** 是否管理员：0否 1是 */
    private Integer isAdmin;

    /** 创建时间 */
    @TableField(fill = FieldFill.INSERT)

package com.buddy.entity;

import com.baomidou.mybatisplus.annotation.*;
import com.baomidou.mybatisplus.extension.activerecord.Model;
import lombok.Data;

import java.time.LocalDateTime;

/**
 * 评价实体
 * 对应数据库表 review
 */
@TableName("review")
@Data
public class Review extends Model<Review> {

    @TableId(type = IdType.AUTO)
    private Long id;

    /** 帖子 ID */
    private Long postId;

import com.baomidou.mybatisplus.extension.activerecord.Model;

/**

### Entity 注解解释

| 注解 | 作用 | 示例 |
|------|------|------|
| `@TableName("sys_user")` | 指定对应的数据库表名 | 类名和表名不一致时必须加 |
| `@TableId(type = IdType.AUTO)` | 标记主键，AUTO 表示数据库自增 | 每个实体都要加 |
| `@TableField(fill = FieldFill.INSERT)` | 插入时自动填充 | createdTime 插入时自动赋值 |
| `@TableField(fill = FieldFill.INSERT_UPDATE)` | 插入和更新时自动填充 | updatedTime 每次修改都更新 |
| `@Data` | Lombok，自动生成 getter/setter/toString 等 | 省去大量样板代码 |
| `extends Model<T>` | MyBatis-Plus ActiveRecord 模式 | 支持 `user.insert()` 这种写法 |

**为什么 `User` 类加 `@TableName("sys_user")` 而其他类不加？** 因为其他类的类名和表名一致（如 `Post` 对应 `post` 表），MyBatis-Plus 默认按类名映射表名（驼峰转下划线）。但 `User` 对应的是 `sys_user` 表，名字不一致，必须显式指定。

### Mapper 解释

- **@Mapper**：告诉 MyBatis 这是一个 Mapper 接口，MyBatis 会为它生成实现类。虽然启动类上已经有 `@MapperScan`，但加上 `@Mapper` 注解是双重保险
- **BaseMapper\<T\>**：MyBatis-Plus 提供的通用 Mapper，自带以下常用方法：

| 方法 | 作用 |
|------|------|
| `selectById(id)` | 根据主键查询 |
| `selectList(wrapper)` | 条件查询列表 |
| `selectPage(page, wrapper)` | 分页查询 |
| `insert(entity)` | 插入一条记录 |
| `updateById(entity)` | 根据主键更新 |
| `deleteById(id)` | 根据主键删除 |
| `selectCount(wrapper)` | 条件查询数量 |

这些方法不用写一行 SQL 就能直接用！如果需要复杂查询，可以在 Mapper 里自定义方法配合 XML 或注解 SQL。
