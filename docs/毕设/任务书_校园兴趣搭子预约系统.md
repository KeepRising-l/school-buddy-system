## 课题意义及要求

**意义：**

本课题旨在设计并实现一个基于 Spring Boot + Vue 的校园兴趣搭子预约系统。在高校校园中，"想找人一起做某件事（打球、电竞、桌游、跑步、自习等）但凑不齐人"是普遍存在的真实需求；而学生现有的解决方式——班级群发消息、表白墙发帖、线下随机相约——普遍存在信息分散、无法按兴趣筛选、缺乏报名确认机制、失约无任何后果等问题。近年来"搭子"作为一种轻社交关系在青年群体中快速流行，反映出场景化、碎片化社交需求的崛起，但现有平台多是内容社区"顺带"提供找搭子能力，缺少面向组局场景的结构化工具与履约约束。

本课题通过"标签匹配 + 状态化预约 + 信誉分约束"三位一体的机制设计，把"找搭子"从发帖拉群升级为结构化流程：组局信息（时间、地点、人数、门槛）全部结构化，报名经过审批，满员进入候补、有人退出自动递补，活动结束后参与者互评；同时用可量化的信誉分约束履约行为，临场取消与爽约留下记录并影响后续使用权限。本课题的研究对探索"信用机制调节小型社区行为"、实践状态机与并发一致性等工程方法具有现实意义，也涵盖了需求分析、系统设计、前后端开发、数据库设计、测试与部署的完整训练链条。

**要求：**

本系统要求采用前后端分离的架构实现。后端基于 Java 语言与 Spring Boot 框架开发，按照业务模块分包组织代码；数据存储使用 MySQL 数据库；认证采用 JWT 令牌机制；前端分为两个独立工程——面向学生的 H5 用户端（Vue 3 + Vant）与面向管理员的 PC 管理端（Vue 3 + Element Plus）。

系统需完成以下核心功能：

（1）**账户与个人资料**：支持学号/手机号注册、登录与登录失败锁定；个人资料编辑（昵称、头像、学院、性别）；兴趣标签与自评段位设置；主页隐私开关与访客主页展示；头像上传按文件内容识别真实类型并做大小与频率限制。

（2）**组局发布与广场**：发布组局帖（标题、分类、兴趣标签、开始/结束时间、地点、人数上限、段位与性别门槛、描述），发布前进行信誉校验、敏感词校验与时间合法性校验；广场支持推荐（按兴趣匹配度个性化排序）、最新、最热三种排序，以及分类、关键词、时间范围筛选，游客可浏览。

（3）**报名、审批与候补**：报名前进行资格校验（信誉分阈值、段位、性别、不可报名自己的组局、防重复报名）；发布者审批报名，满员自动转"已满员"；后来者进入候补队列（先到先得），已有通过者取消时队首自动递补并双向通知；报名与候补支持取消，活动开始前 1 小时内取消已通过报名将被扣除信誉分。

（4）**出勤、评价与信誉分**：活动进行中/结束后由发布者标记出勤或未到场（未到场扣分并通知本人）；活动结束后 7 天窗口内参与者互评（星级 + 标签 + 文字），被评价方可回复一次；信誉分由评价影响与惩罚台账构成，限幅 0~100，低于阈值禁止发帖、禁止报名并在推荐中沉底，恢复后自动解禁。

（5）**通知与运营闭环**：站内通知覆盖新报名、报名结果、候补递补、组局下架/取消、活动开始前提醒、系统消息等类型，支持未读角标与按类型筛选；提供收藏、举报（含去重与自动风控）与公告功能；管理端提供用户管理（封禁/解封/重置信誉分）、帖子管理（下架/删除）、标签管理、举报处置与数据统计（趋势、留存、漏斗、导出）。

（6）**工程质量与安全**：所有状态转换采用"带预期旧状态的条件更新 + 影响行数校验"，防止重复审批、重复取消、超卖等并发问题；关键写接口按用户与动作限流；JWT 密钥外部注入且启动自检；上传、鉴权、CORS、SQL 注入等安全基线齐备；核心业务需编写单元测试并配置持续集成流水线。

在技术实现上，要求自行设计并实现组局（5 种状态）与报名（7 种状态）的状态机，在服务层统一贯彻"条件更新 + 行数校验 + 副作用后置"的并发一致性模式；推荐排序需采用可解释的加权公式（兴趣匹配、时间重合、发布者信誉、热度）并说明设计取舍。最终论文的撰写需完整呈现从需求分析、系统设计、编码实现到测试与部署的全过程，并提供清晰的核心代码与界面展示。

## 学生承担的任务

1. 完成校园兴趣搭子预约系统的需求分析与总体方案设计；
2. 完成后端接口、业务状态机、并发一致性、信誉分与推荐排序等核心模块的编码实现；
3. 完成 H5 用户端与管理端的界面开发与前后端接口联调；
4. 完成系统测试（含单元测试与接口冒烟）、数据库脚本整理与本地部署；
5. 完成毕业论文的撰写，并准备毕业答辩。
