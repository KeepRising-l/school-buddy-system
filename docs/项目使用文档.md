# 校园兴趣搭子预约系统 · 项目使用文档（快速启动）

| 文档属性 | 内容 |
|---------|------|
| 编写日期 | 2026-10-13 |
| 用途 | 在一台新电脑上从零把项目跑起来；含常见问题与演示建议 |
| 适用版本 | backend-v2（Java 17 + Spring Boot 3）+ 两个前端（Vue 3） |

---

## 〇、五分钟版（老手直接看这里）

1. 安装：JDK 17、Maven 3.8+、MySQL 8、Node 18+（默认无需 Redis，见第五节）；
2. 数据库：用 Navicat 或命令行执行 `database/init-all.sql`（会建库建表并灌测试数据）；
3. 后端：把 `backend-v2/src/main/resources/application-local.example.yml` 复制为同目录 `application-local.yml`，填入 MySQL 密码和一个至少 32 位的 JWT 密钥 → 用 IDEA 运行 `BuddyApplication`（或命令行 `mvn spring-boot:run`）；
4. 前端：`cd frontend-h5 && npm install && npm run dev`；另开终端 `cd frontend-admin && npm install && npm run dev`；
5. 打开 `http://localhost:3000`（用户端）和 `http://localhost:3001`（管理端），用 `admin001 / 123456` 登录管理端。

## 一、环境要求

| 软件 | 版本 | 说明 |
|------|------|------|
| JDK | **17**（必须） | 后端要求 Java 17 |
| Maven | 3.8+ | 构建后端 |
| MySQL | 8.x | 数据库 |
| Node.js | 18+（CI 使用 18，22 亦可） | 构建两个前端 |
| Redis | 5+（可选） | **默认不需要**：辅助能力由 MySQL 单表承载；仅当切换 `app.aux.store=redis` 时才需要（见第五节） |
| Navicat（可选） | 任意 | 图形化导入 SQL 更方便 |

> 提示：如果这台电脑同时装了多个 JDK，请确认 IDEA 的 Project SDK 或命令行 `JAVA_HOME` 指向 17。

## 二、数据库初始化

1. 确保 MySQL 已启动；
2. 用 Navicat 打开连接（或命令行 `mysql -u root -p < database/init-all.sql`），执行仓库中：
   - **`database/init-all.sql`** —— 一站式脚本：建库 `school_buddy` + 建 13 张表 + 初始数据 + 测试数据（45 个测试用户、30 条帖子）。
3. 注意：
   - 该脚本包含 `DROP TABLE`，**只能用于本地/测试库**，不要在有真实数据的库上执行；
   - 脚本内置演示管理员 `admin001 / 123456`，生产环境不要使用。
   - 需要更多演示用户时：再运行一次 `database/more-users.sql`（追加 50 个学生账号，账号/密码明细见 `docs/测试用户清单.md`）。

**测试账号**：

| 账号 | 密码 | 角色 |
|------|------|------|
| admin001 | 123456 | 管理员 |
| 20240001 / 20240002 | 123456 | 学生（小明/小红） |
| 2342170101 等批量测试学生 | 学号+"123"（如 2342170101123） | 学生 |

## 三、后端配置与启动

1. 进入 `backend-v2/src/main/resources/`，把 `application-local.example.yml` **复制**为 `application-local.yml`（该文件已被 gitignore，不会提交），填写：

```yaml
spring:
  datasource:
    password: 你的MySQL密码

jwt:
  secret: 至少32位的随机字符串（例如一串32+字符的字母数字组合）
```

2. 说明：
   - 项目**没有任何默认 JWT 密钥**：不配置或不足 32 位，后端会**拒绝启动**（这是安全设计，防止弱密钥上线）；
   - 数据库地址默认 `localhost:3306/school_buddy`，端口或地址不同时在 `application-dev.yml` 里改（或用环境变量覆盖）。
3. 启动方式（二选一）：
   - IDEA：打开 `backend-v2` 目录，运行 `com.buddy.BuddyApplication`；
   - 命令行：`cd backend-v2 && mvn spring-boot:run`（确保 JDK17）。
4. 看到 `Started BuddyApplication` 即成功，服务在 **8080** 端口。
5. （可选）跑一遍测试确认环境：`cd backend-v2 && mvn test`，预期 **135 例全部通过**。

## 四、前端启动

| 端 | 目录 | 命令 | 访问地址 |
|----|------|------|---------|
| 用户端 H5 | `frontend-h5` | `npm install` → `npm run dev` | http://localhost:3000 |
| 管理端 | `frontend-admin` | `npm install` → `npm run dev` | http://localhost:3001 |

- 两个前端的开发服务器都已把 `/api` 代理到 `http://localhost:8080`，只要后端在跑，直接访问页面即可；
- 依赖安装慢时可用国内镜像：`npm install --registry=https://registry.npmmirror.com`。

## 五、辅助数据存储（默认 MySQL，无需 Redis）

登录失败锁定、浏览量去重、上传频率限制、举报去重这四类"辅助数据"由统一组件承载，**默认使用 MySQL 单表 `aux_kv`，零外部依赖**——不需要安装 Redis。

**已有旧数据库升级（一次性）**：在 `school_buddy` 库执行下面这段（用 `init-all.sql` 新导入的库已自带该表）：

```sql
CREATE TABLE IF NOT EXISTS `aux_kv` (
    `k`           VARCHAR(128) NOT NULL COMMENT '键',
    `v`           BIGINT       NOT NULL DEFAULT 1 COMMENT '值（计数）',
    `expire_time` DATETIME     NOT NULL COMMENT '过期时间',
    PRIMARY KEY (`k`),
    KEY `idx_expire` (`expire_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='辅助键值表';
```

**可选：切换为 Redis**（数据量大、并发高或觉得 MySQL 版响应偏慢时，可无痛切换）：

1. 启动一个 Redis（Windows 可用 Memurai，或下载 tporadowski 维护的 Redis for Windows，解压后运行 `redis-server.exe`；亦可使用 WSL / 局域网现有 Redis）；
2. 在 `application-local.yml` 中加一行：`app.aux.store: redis`；
3. 重启后端即可。业务代码零改动，两套实现行为一致，可随时改回 MySQL。

## 六、验证清单（跑起来后按顺序点一遍）

1. 管理端登录 → 数据看板有数据（总用户 45+，导入 `more-users.sql` 后 95+、帖子 30+）；
2. H5 游客浏览广场 → 分类/排序/搜索均可用；
3. 学生账号登录 → 发布一条"未来时间"的组局（例如 2 小时后开始）→ 广场可见；
4. 换第二个学生账号报名 → 发布者审批通过 → 人数 +1 → **双方详情页出现「联系方式」卡片（手机号可一键拨号）**；
5. 取消报名 → 人数 -1；把报名审核拒掉（**被拒者/未报名者的详情页只显示"报名通过后可查看联系方式"**）；
6. 详情页发评论；管理端把它下架 → H5 不可见；
7. 管理端封禁一个用户 → 该用户登录被拒；
8. **发一条 31 分钟后开始、已有人报名的组局，等 5 分钟内触发提醒任务 → 参与者与发布者的消息中心出现"活动即将开始"（同一人同一局只会收到一次）**；
9. **消息中心顶部切换「报名/活动提醒/组局变动/系统」页签 → 列表随类型筛选**；
10. **管理端「数据统计 → 举报处理」→ 有总量/处理率/平均处理时长指标卡与每日举报量折线图**。

## 七、常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 后端启动失败，提示"JWT 密钥未配置/长度不足" | 没有配 `application-local.yml` 或密钥短于 32 字符，按第 3 步补齐 |
| 启动报数据库连接错误 | MySQL 没启动 / 密码不对 / 库没建（重跑 init-all.sql）；确认 `school_buddy` 库存在 |
| 登录提示"系统繁忙，请稍后重试" | 辅助存储不可用：默认模式下多为数据库异常（检查 MySQL 连接）；若已切换 `app.aux.store=redis`，检查 Redis 是否启动 |
| 提示 `Table 'school_buddy.aux_kv' doesn't exist` | 旧库未升级：执行第五节的一次性建表 SQL，或重新导入 `init-all.sql` |
| 登录提示"账号或密码错误" | 用测试账号（admin001/123456）或批量学生的"学号+123" |
| 页面能开但接口 404/网络错误 | 后端没启动或不在 8080；检查前端终端里 `/api` 代理目标 |
| 端口被占用（8080/3000/3001） | 关掉占用的进程，或改对应配置（后端 server.port / 前端 vite server.port，同时更新另一端代理） |
| 上传头像后图片 404 | 确认后端启动目录为 `backend-v2`（上传目录基于启动目录生成）；`backend-v2/uploads/` 会自动创建 |
| 发布组局被拒：时间不合法/时长超限 | 开始时间必须"晚于当前时间"，活动时长不超过 24 小时 |
| 帖子导入后很快全部"已结束" | 示例数据的时间是过去日期（系统会用定时任务推进状态）；**演示时请现场造"未来时间"的帖子** |
| 收不到"活动即将开始"提醒 | 提醒只针对"开始时间在未来 30 分钟内"且已过审的组局，且每 5 分钟扫描一次；确认帖子时间与报名状态，或直接把开始时间改到 10 分钟后 |
| 报名通过了还是看不到对方手机号 | 双方手机号来自用户资料 `phone` 字段，为空则不展示；确认该用户在"我的资料"里填了手机号 |
| 提示"操作过于频繁，请稍后再试" | 触发了接口限流（发布 5 次/时、评论 20 次/时、报名/候补 10 次/时、举报 10 次/时）；等待窗口结束或改配置常量后重启 |

## 八、演示与截图建议（答辩用）

1. 演示前 10 分钟：启动后端/双前端 → 用发布者账号**造 1-2 条未来时间的帖子** → 开好两个浏览器窗口（H5 + 管理端）；
2. 推荐主链路：发布（故意触发一次时长或敏感词拦截）→ 报名 → 审批 → 满员 → 候补 → 取消触发自动递补 → 出勤标记 → 互评 → 信誉分变化 → 管理端举报处置/封禁/导出；
3. 可截图留档：广场推荐排序、报名管理弹窗、数据看板、留存/漏斗图、CI 测试全绿页面。
