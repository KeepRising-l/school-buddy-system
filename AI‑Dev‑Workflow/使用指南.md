# 使用指南

> 本文档说明如何在真实项目中使用这套 AI 软件开发工作流。
>
> 阅读对象：使用工作流的「你」。
>
> AI 的行为规则在各个 Skill 中，本文只告诉你怎么发起、怎么配合、怎么收尾。

------

# 一、快速开始（三步）

```text
① 拷贝
把本工作流文件夹复制到你的新项目目录。

② 开场
新会话第一句话告诉 AI 你要做什么（开场白见下文）。

③ 配合
按阶段配合 AI：AI 产出 → 你审查 → 你确认冻结 → 进入下一阶段。
```

就这么简单。其余的一切由总控 Skill 驱动 AI 完成。

------

# 二、开场白（新项目）

新会话第一句话这样说：

```text
请先阅读 00_总控/Skill_总控_四模块协作与工作流编排_V1.md
和 00_总控/项目状态.md，按总控流程启动一个新项目。
我想做一个〈你的产品想法〉。
```

AI 会：

```text
读取项目状态（发现是新项目）
    ↓
进入模块一：需求规划
    ↓
开始和你梳理需求
```

------

# 三、完整生命周期

```text
模块一：需求规划
    「做什么？」
    AI 推演 + 追问 → 产出《产品需求与业务规格》
        ↓  你确认冻结 REQ-V1
模块二：技术设计
    「怎么做？」
    AI 设计 + Demo 验证 → 产出《技术设计文档》
        ↓  你确认冻结 TECH-V1
模块三：交互原型与视觉验证
    「用户看到什么、怎么操作？」
    AI 产出原型 + Wireframe + 交互 Demo
        ↓  你确认冻结 PROTO-V1
模块四：开发规划与 MVP 实现
    「怎么真正做出来？」
    AI 先产出开发计划，再按业务切片逐个实现
        ↓  你验收 MVP
项目完成 / 继续迭代
```

关键点：

> **前三个阶段全部冻结后，AI 才会开始正式开发。**

------

# 四、每个阶段的操作循环

你和 AI 在每个阶段都重复同一个循环：

```text
AI：推演 / 产出该阶段文档
    ↓
你：审查，提修改意见（或认可）
    ↓
AI：修改，直到满足该阶段闸门条件
    ↓
你：说「确认冻结〈阶段〉〈版本号〉」
    ↓
AI：写入冻结状态 → 更新项目状态.md → Git Commit
    ↓
自动进入下一阶段
```

你的职责只有三件事：

1. **回答问题**：AI 只会在影响产品行为的地方追问，不会问琐碎细节；
2. **审查产物**：文档、原型、Demo 是你的验收对象；
3. **触发冻结**：冻结永远由你的一句话启动。

------

# 五、标准冻结确认（最重要的一节）

冻结由你显式触发，标准句式：

```text
确认冻结需求基线 REQ-V1。
确认冻结技术基线 TECH-V1。
确认冻结原型基线 PROTO-V1。
```

注意：

> 「嗯」「可以」「继续」「先这样」**不构成冻结**。
>
> AI 收到含糊回复时只会继续当前工作，不会写入冻结状态。

如果你不想冻结，只是让它继续干活，直接说「继续」即可，两者不会混淆。

这是整套流程严肃性的核心开关：**AI 永远不会替你宣布「已经确认」。**

------

# 六、模块四：开发阶段怎么配合

三个基线冻结后，AI 进入模块四。注意：

> **AI 不会一口气生成整个 MVP。**

实际节奏：

```text
AI：产出《开发计划》（MVP 范围 + 任务拆解）
    ↓
AI：实现第 1 个业务切片（如用户登录闭环）
    ↓
AI：运行 + 自验证（成功 / 失败 / 越权场景）→ Commit
    ↓
你：运行抽查，提问题
    ↓
AI：下一个切片……直到核心业务闭环跑通
    ↓
你：MVP 验收
```

MVP 的完成标准不是「代码写完了」，而是：

- 项目可运行；
- 核心业务闭环可执行；
- 异常 / 权限 / 状态已验证；
- 你能完成核心任务。

开发中发现设计有问题时，AI 不会硬写也不会偷偷改，而是按层级回退：需求问题回模块一、技术问题回模块二、原型问题回模块三，重新确认、重新冻结（版本升为 V2）后再继续。

------

# 七、跨会话续接（断线 / 换 AI）

随时关掉会话都不怕。下次开新会话，只要说：

```text
读取 00_总控/项目状态.md，继续当前项目。
```

新 AI 会按接手顺序自己恢复进度：

```text
读项目状态 → 判断当前阶段 → 读当前阶段 Skill 摘要
→ 读冻结产物 → 检查 Git → 继续工作
```

不需要你复述任何历史对话。项目事实的三层存储：

```text
项目状态.md  → 现在进行到哪了
冻结产物     → 已经确定了什么
Git          → 历史上发生过什么
```

# 八、常见场景速查

## 场景 1：项目很小（如个人 CLI 工具、后端脚本）

告诉 AI：

```text
这个项目规模很小，请按总控 7.5 节提出流程裁剪建议。
```

AI 会提议压缩或跳过某些阶段（如无界面项目跳过模块三），并记录裁剪决定。裁剪只减环节，不降闸门质量。

## 场景 2：中途想改需求

不要直接说「把 XX 改一下」然后让它在代码里顺手改。正确做法：

```text
我认为〈某业务规则〉需要调整为〈新规则〉，
请按变更流程处理。
```

AI 会判断变更层级 → 回退对应模块 → 重新确认 → 重新冻结 → 传播检查后续阶段。

## 场景 3：AI 提出了你没确认过的东西

检查项目状态.md 里的信息等级：

- 🟢 已确认：可以作为事实；
- 🟡 待确认 / 🔴 AI 推测：AI 不得自行采用，需要你表态。

如果你发现 AI 把推测当事实用了，直接指出，它会按防幻觉规则纠正。

## 场景 4：AI 和你想法冲突（如技术方案实现困难）

AI 不允许因为实现方便就修改产品行为。它应该向你说明冲突并请求决策。如果它偷偷改了，冻结基线和 Git 历史会让这种改动暴露出来。

## 场景 5：接管一个已经做了一半的项目

```text
请阅读 00_总控/项目状态.md 和已有产物，
按总控第 6 节接管流程，判断当前进度并继续。
```

AI 不会强制从模块一重来。

## 场景 6：重构一个旧项目（没用过工作流的存量代码）

开场白：

```text
请先阅读 00_总控/Skill_总控_四模块协作与工作流编排_V1.md
和 00_总控/Reference_总控_存量项目重构_V1.md，
我要重构〈旧项目路径〉这个已有项目，请进入存量项目重构模式。
```

AI 会：

```text
读旧代码 → 产出《现状说明》供你核对
    ↓
反向生成三份草稿（🟡 待确认）：
需求文档 + 技术设计 + 全页面 Wireframe
    ↓
追问意图（去留、垃圾点、期望）
    ↓
你修改 → AI 同步三份草稿
    ↓
你看满意 → 确认冻结 REQ-V1 / TECH-V1 / PROTO-V1
    ↓
进入开发，按切片实现 MVP
```

三条护栏：

- 反向生成的文档是草稿，AI 不会自动冻结，冻结仍由你显式触发；
- 代码行为 ≠ 你的意图：AI 会问「这是本意还是当时没做」；
- 你改任何一处，AI 会同步检查另外两份文档。

# 九、常见误区

| 误区 | 正确做法 |
|---|---|
| 「文档攒够了，最后一次性让 AI 生成整个项目」 | 开发是逐切片实现、逐个验证的，不是一次性生成 |
| 「AI 说做完了就冻结」 | 完成 ≠ 冻结，冻结必须由你说「确认冻结 XX-V1」 |
| 「聊天记录里确认过就行了」 | 重要事实必须进入项目状态.md 和产物，聊天不是记忆 |
| 「开发时发现设计不对，让 AI 直接改代码迁就」 | 按层级回退到对应模块重新确认，不在错误的层级打补丁 |
| 「小项目也要走完四道闸门」 | 用 7.5 流程裁剪，流程服务于项目，不是项目伺候流程 |
| 「MVP 功能越少越好」 | MVP 是能验证核心价值的最小完整闭环，不是功能阉割版 |

------

# 十、一句话总结

> 拷贝模板 → 开场告诉 AI 想法 → 前三阶段 AI 与你反复确认并产出文档 → 你逐个显式冻结 → AI 按切片实现 MVP，边做边验证 → 验收。
>
> 你的角色是**决策者**：回答问题、审查产物、触发冻结。
>
> AI 的角色是**执行者**：推演、产出、实现、验证，且永不越过你划定的边界。
