# 开发计划（MVP）V1 —— 模块四

> 依据：REQ-V1 / TECH-V1 / PROTO-V1 三份冻结基线 + 《现状说明 V1》23 条规则清单。
>
> 特别说明：本项目为存量重构（D-004/D-005），MVP 范围 = **功能集全量等价迁移**（15 个 H5 页面 + 8 个管理端页面 + 23 条业务规则），不存在功能裁剪意义上的 P0/P1 分级；切片顺序按**业务依赖**排列，核心闭环（发局→报名→审批→候补→出勤→互评→信誉）的切片优先。
>
> 前端零改动（D-012）：每个切片完成 = 后端行为可用并可独立验证；前后端联调统一在切片 S9 进行回归。

---

## 一、MVP 边界

MVP 必须完成（等价迁移）：

- 用户端：认证、用户、帖子、报名、评价、信誉分、广场推荐、收藏、通知、举报、标签、公告、头像上传；
- 管理端：用户管理、帖子管理（下架/删除）、标签管理、举报中心、公告管理、统计与三类导出；
- 逻辑删除+级联（D-007）、审核简化为敏感词校验（D-006）、取消组局不扣分自动通知（D-008）、通知 7 类（D-011）。

MVP 不实现（维持旧版边界）：

- 消息推送（WebSocket）、管理员审计日志、云存储（G3/G4/A3 维持现状）；

## 三、切片任务清单

### S0 Demo 验证（✅ 已完成 2026-09-07）

backend-v2 空壳 + auth/user 最小闭环，冒烟全过（见项目状态 C-002）。

### S1 通知模块（notification）

- 目标：8→7 类通知的发送与查询能力（D-011）；等价迁移 NotificationServiceImpl 的发送逻辑（同事务 insert）。
- 范围：entity/mapper/service/impl + 用户端 NotificationController（list/unread-count/read/read-all）。
- 完成标准：发送→查询→未读数→已读全链路可用；通知类型不含「帖子审核」。
- 验证：API 实测（发送一条、未读数变化、已读后未读数归零）。

### S2 信誉分模块（credit）

- 目标：100 + Σ评价影响 + Σ台账，限幅 [0,100]；五档等级；标签影响映射（靠谱/友好/技术好 +2、准时 +1、迟到/态度差 -3、爽约 -10，星级兜底）；recordPenalty（临场取消 -5 / 爽约 -10 / 管理员重置，写台账即时重算）；CreditCalculateTask 每日全量重算。
- 完成标准：getCreditLevel/Label 输出与旧版逐档一致；UserVO 的 creditLevel/creditLabel 补齐（消除 Demo 遗留）；惩罚不被每日重算冲掉。
- 验证：构造不同分值/台账组合，新旧实现输出对照；重算任务手动触发一次核对全量结果。

### S3 帖子模块（post）

- 目标：发布（敏感词校验，命中拒绝，发布即可见）/详情（浏览计数）/评论/取消组局（非终态）+ PostStateMachine 等价迁移 + PostStatusTask 定时推进（仅推进可见帖）+ SensitiveWordService 迁移 + 逻辑删除字段与级联基础（deleted 字段、@TableLogic 配置）。
- 完成标准：RECRUITING↔FULL→ONGOING→FINISHED、非终态→CANCELLED 与旧版一致；状态机拒绝非法流转；取消组局时 APPROVED 报名自动取消+逐个通知+不扣分（依赖 S1；apply 模块未建前先以 SQL 级联验证，S4 接管）。
- 验证：状态机用例逐边验证；定时任务手动触发核对状态推进；敏感词命中用例。

### S4 报名模块（apply）——核心闭环心脏

- 目标：报名（资格三重校验：信誉≥60+段位+性别；不能报自己的局；取消/被拒后可重报复用记录）、候补（FULL 自动 WAITLIST，FIFO，队首递补为 PENDING+双方通知）、审批（条件更新防并发 + 原子人数 SQL 防超卖）、取消（PENDING/APPROVED/WAITLIST 可取消且帖子须 RECRUITING/FULL；开始前 1h 内取消 APPROVED 扣 5 分）、收到的申请、出勤标记（ATTENDED/NOSHOW；进行中不可 NOSHOW；结束后 24h 窗口；NOSHOW 扣 10 分+通知）。
- 完成标准：发局→报名→审批→满员→候补→递补→出勤全链路真实走通；并发重复审批/取消/标记行为与旧版一致（不超卖、不重复扣分）。
- 验证：全链路 Happy Path + 分支路径（资格不足/重复报名/重复审批/超员边界）+ 与旧代码逐条对照。

### S5 评价模块（review）

- 目标：活动结束互评（1-5 星+标签+文字，同人同局一次）、被评价人回复一次、评价→信誉重算联动。
- 完成标准：互评闭环可用；评价后信誉分按标签映射正确变化；重复评价被拒绝。
- 验证：互评→查信誉分变化→回复→重复评拒绝。

### S6 广场与推荐（square）

- 目标：推荐公式（0.4/0.3/0.2/0.1 + 低信誉 ×0.3 + 游客简化公式）、latest/hot 排序、分类/关键词/时间筛选、分页。
- 完成标准：三种排序与筛选结果与旧版一致；脏标签容错跳过。
- 验证：与旧版同库同参数对照输出（同数据集排序一致）；筛选边界用例。

### S7 用户端叶子模块（favorite/report/tag/announcement/file）

- 目标：收藏四接口、举报提交与进度、标签查询、公告弹窗拉取、头像上传（jpg/png ≤2MB 魔数校验，本地存储）。
- 完成标准：各接口行为与旧版一致；上传校验用例通过。
- 验证：逐接口 API 实测 + 上传异常用例（超限/类型不符）。

### S8 管理端全量

- 目标：各业务模块 admin/ 子包（AdminUser 封禁/解封/信誉调整、AdminPost 下架/逻辑删除+级联、AdminTag、AdminReport 处理、AdminAnnouncement）+ module/admin 统计聚合（overview/9 类图表数据）+ 三类导出。
- 完成标准：@RequireAdmin 权限拦截生效（未登录 401/非管理员 403）；管理端 8 页面所需接口全部可用；删除帖子级联逻辑删除四张关联表。
- 验证：管理接口权限矩阵实测；下架→广场不可见；删除→级联核对数据库。

### S9 回归联调 + MVP 验收

- 目标：两个前端（零改动）接入 backend-v2 全页面走查；《现状说明》23 条规则逐条核对；REQ-V1 §11 验收标准逐项验证。
- 完成标准：REQ-V1 验收标准 5 条全过（全链路闭环、管理端八项、状态机一致、并发一致、Java 17+Boot 3 运行）。
- 验证：按验收清单执行并记录结果 → 用户确认 MVP 验收。

## 四、推进纪律

1. 严格按切片顺序推进，每片「实现→运行→验证→Git Commit→下一片」；
2. 每片完成更新项目状态.md 当前工作单元；
3. 开发中发现基线问题：判断层级（产品/技术/原型/实现），实现问题就地修，前三类按流程回退，不偷偷改冻结内容；
4. 迁移时以旧代码为行为基准，逐条对照《现状说明》23 条规则；
5. 构建命令统一：`$env:JAVA_HOME='D:\develop\JDK17'; mvn -s backend-v2\.mvn\settings-local.xml -f backend-v2\pom.xml package -q`。
