# 1. 产品概述

## 产品目标

为在校大学生提供「找搭子」平台：发起兴趣组局、报名参加、活动后互评，用信誉分机制约束守约行为。

## 解决的问题

- 学生想找兴趣相投的搭子（球类/电竞/桌游/跑步）缺少渠道；
- 临时组局缺乏约束，爽约、放鸽子成本低；
- 线下拉群组织效率低、信息分散。

## 核心价值

- 组局信息结构化（时间/地点/人数/门槛），报名审批线上化；
- 信誉分体系让「靠谱」可量化、可积累；
- 候补机制提高名额利用率。

## 产品范围

- 用户端 H5（移动浏览器访问）：组局发布/浏览/报名/评价/个人中心；
- 管理端（PC Web）：用户/帖子/标签/举报/公告/统计管理；
- 不含：Native App、即时聊天、支付。

# 2. 用户与角色

| 角色 | 说明 | 核心操作 |
|---|---|---|
| 游客 | 未登录用户 | 浏览广场、查看帖子详情、查看他人主页 |
| 学生用户 | 注册登录的在校生 | 发布组局、报名/候补、取消报名、收藏、评论、评价、管理自己收到的报名、设置标签与隐私、查看通知与举报进度 |
| 管理员 | is_admin=1 的用户 | 审核帖子、下架、删除帖子、封禁/解封用户、调整信誉分、管理标签、处理举报、管理公告、查看统计与导出 |

# 3. 核心业务对象

- **用户（User）**：学号唯一，含信誉分、状态、隐私开关；
- **组局帖子（Post）**：由用户发布，有生命周期状态，含门槛（段位/性别）与人数上限；
- **报名（PostApply）**：用户对帖子的参与申请，有审批与出勤状态；
- **评价（Review）**：活动结束后参与者之间互评，影响信誉分；
- **信誉分台账（CreditLog）**：非评价类信誉变动的流水；
- **通知（Notification）**：业务事件触发的站内通知；
- **兴趣标签（InterestTag）/用户标签（UserTag）**：管理员维护标签，用户自选并自评段位；
- **收藏（Favorite）/评论（PostComment）/举报（Report）/公告（Announcement）**。

关系：用户 1—N 帖子；用户 N—N 帖子（经报名）；帖子 1—N 报名/评论/评价/收藏；评价 N—1 信誉分（经重算）；管理员维护标签与公告。

# 4. 核心业务流程

## 4.1 组局主流程

发布组局（敏感词校验通过后立即在广场可见，无人工审核环节）→ 他人报名 → 发布者审批（通过则占用名额）→ 满员转 FULL（后来者进候补）→ 定时任务到 start_time 转 ONGOING → 到 end_time 转 FINISHED → 参与者互评 → 信誉分更新。【用户确认简化：审核仅保留敏感词校验】

## 4.2 报名审批流程

报名（资格校验：信誉分≥60 + 段位 + 性别）→ PENDING → 发布者通过（人数+1，满则帖转 FULL）/ 拒绝 → 通知报名者。

## 4.3 候补递补流程

FULL 帖子报名 → 自动转 WAITLIST（FIFO 排队，通知排位）→ 有 APPROVED 报名取消 → 队首自动递补为 PENDING → 双方收到通知 → 发布者重新审批。

## 4.4 出勤与信誉流程

活动进行中/结束后，发布者标记参与者 ATTENDED / NOSHOW → NOSHOW 扣 10 分（写台账、即时重算、通知本人）→ 进行中不可标 NOSHOW，结束后 24 小时内必须标记完毕。

# 5. 功能需求（按业务模块组织）

## 5.1 认证模块

- 注册：学号唯一、用户名唯一、手机号唯一，BCrypt 存密码；【代码现状】
- 登录：用户名/密码，签发 JWT（7 天）；【代码现状】
- 游客可选登录：无 Token 可浏览公开内容。【代码现状】

## 5.2 用户模块

- 个人资料查看/编辑（昵称/头像/签名/学院/性别）；
- 兴趣标签设置（选择标签 + 自评段位 1-5）；
- 主页隐私开关（隐藏历史组局）；
- 他人主页（昵称/头像/信誉等级/评价列表，隐私开关生效）；
- 我的发布 / 我的报名 / 我的收藏 / 我的举报入口。【代码现状】

## 5.3 帖子模块

- 发布：标题/分类/标签/起止时间/地点/人数/段位与性别门槛/描述；【代码现状】
- 敏感词校验：发布与评论时命中违禁词则拒绝提交；发布成功即可见，无人工审核环节；【代码现状（敏感词拦截）+ 用户确认简化（去掉人工审核）】
- 详情：含浏览计数、评论列表；
- 评论：文字评论（500 字内）；
- 发布者取消组局：非终态可取消；【代码现状】
- 状态机：RECRUITING ↔ FULL → ONGOING → FINISHED，非终态 → CANCELLED，终态不可流转。【用户确认保留】

## 5.4 报名模块

- 报名（资格三重校验；不能报自己的局；取消/被拒后可重报）；
- 候补（FULL 自动进队，FIFO，自动递补）；
- 取消（PENDING/APPROVED/WAITLIST 可取消且帖子须为 RECRUITING/FULL；开始前 1 小时内取消 APPROVED 扣 5 分）；
- 审批（仅发布者，仅 PENDING，条件更新防并发，原子加人数防超卖）；
- 收到的申请列表；
- 出勤标记（见 4.4）。【代码现状，用户确认保留】

## 5.5 评价模块

- 活动结束后互评：1-5 星 + 标签（靠谱/爽约/迟到等）+ 文字；
- 同一局内对同一人仅评一次；
- 被评价人可回复一次。【代码现状】

## 5.6 信誉分模块

- 100 分制；信誉分 = 100 + Σ评价影响 + Σ台账变动，限幅 [0,100]；
- 评价影响：标签为主（靠谱/友好/技术好 +2，准时 +1，迟到/态度差 -3，爽约 -10），星级兜底；
- 台账：临场取消 -5 / 爽约 -10 / 管理员重置，即时重算生效；
- 等级五档（靠谱队友/优质/普通/需改善/失信）；
- 低于 60：不可报名 + 发布帖子推荐沉底 ×0.3；
- 每日全量重算。【代码现状，用户确认原样保留（D-004 追问轮）】

## 5.7 广场与推荐模块

- 列表：推荐（加权公式）/最新/最热三种排序；
- 筛选：分类、关键词（标题/地点/描述）、时间范围（今天/本周/本月）；
- 推荐公式：0.4×标签匹配 + 0.3×时间重合 + 0.2×发布者信誉 + 0.1×热度；游客用简化公式。【代码现状】

## 5.8 收藏 / 通知 / 举报 / 标签 / 公告 / 文件模块

- 收藏：加/取消/列表/状态查询；【代码现状】
- 通知：7 类业务通知（旧版 8 类，去除「帖子审核」通知类型，见 D-011）、未读数、单条/全部已读；【代码现状 + 用户确认简化】
- 举报：针对帖子/用户，类型+说明；我的举报进度；【代码现状】
- 标签：管理员增改禁，分类查询；【代码现状】
- 公告：类型（公告/弹窗）、发布/关闭、过期时间、H5 弹窗拉取；【代码现状】
- 文件：头像上传（jpg/png ≤2MB，魔数校验，本地存储）。【代码现状】

## 5.9 管理端

- 用户管理：列表/详情（含其帖子/报名/评价）/封禁/解封/信誉分调整；
- 帖子管理：列表/下架（举报处置用）/删除；
- 标签管理：增/改/禁用；
- 举报中心：列表/详情/处理（有效/无效）；
- 公告管理：增删改/发布/关闭；
- 统计：总览/帖子/成局率/活跃/分类分布/信誉分布/用户增长/留存/漏斗 + 用户/帖子/统计三类导出。【代码现状】

# 6. 状态与生命周期

## 帖子

创建（RECRUITING，敏感词校验通过即可见）→ 审批满员（FULL）→ 到开始时间（ONGOING，定时任务）→ 到结束时间（FINISHED，终态）；任意非终态可被发布者取消或管理员下架/删除（CANCELLED 终态 / 逻辑删除）。【用户确认保留状态机；审核简化为敏感词校验】

## 报名

PENDING → APPROVED / REJECTED；PENDING/APPROVED/WAITLIST → CANCELLED；APPROVED → ATTENDED / NOSHOW；FULL 帖报名 → WAITLIST → 递补为 PENDING。【代码现状】

## 用户

注册（正常 status=1）→ 管理员封禁（status=0，Token 立即失效式拒绝）→ 解封。【代码现状】

## 公告

创建（关闭）→ 发布（启用）→ 关闭；含过期时间。【代码现状】

# 7. 权限与产品边界

- 游客：只读公开内容（广场/详情/他人主页），不能任何写操作；
- 学生用户：只能改自己的资料/标签/隐私；只能取消自己的报名；只能审批/标记自己发布帖子的报名与出勤；只能看自己帖子的报名列表；
- 管理员：管理端全部接口（@RequireAdmin）；
- 封禁用户：所有需登录接口拒绝（403）；
- 数据可见性：所有发布成功的帖子对所有人可见（无待审核态）；被管理员下架的帖子不可见且不可报名；他人主页历史组局受隐私开关控制。【用户确认】

# 8. 业务对象关联

- 删除帖子：**逻辑删除**，同时级联逻辑删除其评论/报名/评价/收藏（数据保留可追溯）；【用户确认】
- 封禁用户：其历史帖子/报名保留，但登录被拒；【代码现状】
- 发布者取消组局：已通过（APPROVED）的报名自动转 CANCELLED 并逐个通知本人，**不扣任何人的信誉分**；候补记录一并取消；【用户确认】
- 评价删除：不支持（无删除入口）。【代码现状】

# 9. 异常与边界规则

- 并发场景：重复审批/重复取消/重复标记用条件更新幂等；审批超卖用原子 SQL；【代码现状】
- 帖子标签脏数据（非法 ID）容错跳过不炸广场；【代码现状】
- 报名唯一键冲突通过复用旧记录规避；【代码现状】
- Token 过期/无效返回 401，权限不足 403。【代码现状】

# 10. 关键业务规则汇总

见第 5 节各模块规则，全部源自【代码现状】并经用户意图追问确认保留（D-004）；其中「发布即可见+敏感词校验（去人工审核）」「信誉分体系原样保留」「逻辑删除+级联」「取消组局不扣分自动通知」为用户显式裁决。

# 11. 验收标准

重构后的 MVP 验收 = 现有功能全部等价迁移并可验证：

1. 注册→登录→发帖→他人报名→审批→满员→候补→递补→出勤标记→互评→信誉分变化，全链路可走通；
2. 管理端八项管理能力可用；
3. 帖子状态机流转与旧版行为一致；
4. 并发重复操作行为一致（不超卖、不重复扣分）；
5. 前后端在 Java 17 + Boot 3 环境下正常运行。
