# 1. 项目概况

一句话：**校园兴趣搭子预约系统**——学生发布「组局」帖子，其他人报名参加，发布者审批，活动结束后互评并影响信誉分；配套管理端负责用户、帖子、标签、举报、公告与统计。

技术栈（实际代码为准）：

| 层 | 技术 |
|---|---|
| 后端 | Java 8 + Spring Boot 2.7.18 + MyBatis-Plus 3.5.5 + MySQL 8 + Redis（Lettuce）+ JWT(jjwt 0.11.5) + Hutool，Maven 构建 |
| 用户端 H5 | Vue 3.4 + Vite 5 + Vue Router 4 + Pinia + Axios + Vant 4 |
| 管理端 | Vue 3.4 + Vite 5 + Vue Router 4 + Pinia + Axios + Element Plus 2.6 + ECharts 5 |
| 数据库 | 10 张表（schema.sql），另有测试数据脚本（test-data.sql、more-posts.sql 等） |
| 外部依赖 | 本地 MySQL（localhost:3306/school_buddy）、本地 Redis（localhost:6379），无第三方云服务 |

## 2.5 定时任务（3 个）

- **PostStatusTask**：每 5 分钟，到 start_time 且已审核的帖子 → ONGOING；到 end_time → FINISHED（仅推进已审核通过的帖子）
- **CreditCalculateTask**：每日重算全量信誉分
- **ActivityRemindTask**：活动开始前提醒（通知中心）

# 3. 隐含业务规则（从代码反推，逐条标注【代码现状】）

## 帖子生命周期

1. 【代码现状】帖子状态机：RECRUITING ↔ FULL → ONGOING → FINISHED，任意非终态可 → CANCELLED；FINISHED/CANCELLED 为终态（PostStateMachine.java）
2. 【代码现状】先发后审（V1.3）：帖子发布即可见（is_audit_pass 有 0/1/2 三态：待审核/通过/下架）；管理员可下架（audit → is_audit_pass=2），下架后不可报名/候补/审批（ApplyServiceImpl）
3. 【代码现状】定时任务只推进「已审核通过」的帖子（PostStatusTask）

## 报名闭环

4. 【代码现状】报名门槛三重校验：信誉分 <60 不可报名（PUNISH_THRESHOLD=60）+ 段位要求（用户在帖子任一标签上的最高自评段位 ≥ requireLevel）+ 性别限制（ApplyServiceImpl.validateQualification）
5. 【代码现状】不能报名自己发布的组局；CANCELLED/REJECTED 后可重新报名（复用旧记录行，规避唯一键冲突）
6. 【代码现状】满员后报名自动转候补（WAITLIST）；候补按报名时间 FIFO，APPROVED 报名被取消后队首自动递补为 PENDING（ApplyServiceImpl.promoteWaitlist）
7. 【代码现状】审批、取消、出勤标记均用「条件更新」（只允许从预期状态流转）防并发重复操作；审批通过人数用原子 SQL 自增防超卖（ApplyServiceImpl）
8. 【代码现状】取消规则：仅 PENDING/APPROVED/WAITLIST 可取消，且帖子须为 RECRUITING/FULL；活动开始前 1 小时内取消且状态为 APPROVED 扣信誉分 -5（PENDING/WAITLIST 不扣）（ApplyServiceImpl.cancelApply）
9. 【代码现状】出勤规则：发布者标记 ATTENDED/NOSHOW；进行中不能标 NOSHOW；活动结束后 24 小时内必须标记完毕；NOSHOW 扣 -10 并发通知（ApplyServiceImpl.markAttendance）

## 信誉分体系

10. 【代码现状】信誉分 = 100 + Σ评价影响 + Σ台账变动，限幅 0-100；每日重算（CreditServiceImpl）
11. 【代码现状】评价影响以「标签」为主计算：靠谱/友好/技术好 +2，准时 +1，迟到/态度差 -3，爽约 -10；无标签时按星级兜底（5星+2 / 4星+1 / ≤2星-3）（CreditServiceImpl.calculateReviewImpact）
12. 【代码现状】临场取消 -5、爽约 -10、管理员重置，写 credit_log 台账并即时重算，惩罚不被每日重算冲掉（V1.2 机制）
13. 【代码现状】信誉等级五档：≥90 靠谱队友 / ≥75 优质 / ≥60 普通 / ≥40 需改善 / <40 失信（CreditServiceImpl）
14. 【代码现状】发布者信誉分 <60 时其帖子推荐权重 ×0.3 沉底（RecommendServiceImpl）

## 推荐算法

15. 【代码现状】推荐分 = 0.4×标签匹配度 + 0.3×时间重合度 + 0.2×(发布者信誉/100) + 0.1×热度(人数比)；已登录无标签用户或游客用简化公式（0.5×时间 + 0.3×热度 + 0.2×标签）；时间重合度 = 1 - 距开始小时数/168（7 天封顶）；Redis 缓存 5 分钟（RecommendServiceImpl）
16. 【代码现状】广场支持 latest（默认）/hot（按 current_people）两种普通排序 + 推荐排序；分类/关键词（标题/地点/描述 like）/时间范围（today/week/month）筛选（RecommendServiceImpl）

## 认证与权限

17. 【代码现状】JWT 放在 Authorization: Bearer 头，7 天有效；Spring Security 全放行，认证完全由自定义 JwtInterceptor 处理；无 Token 按游客放行（可选登录模式），带 Token 解析身份（JwtInterceptor）
18. 【代码现状】管理权限通过 @RequireAdmin 注解 + is_admin 字段校验；封禁用户即使 Token 未过期也直接 403（JwtInterceptor）
19. 【代码现状】JWT 密码有默认开发值（环境变量 JWT_SECRET 可覆盖）；数据库密码走 application-local.yml（gitignore）+ 环境变量（application-dev.yml）

## 其他

20. 【代码现状】头像上传仅限 jpg/png ≤2MB，有魔数校验，存本地 uploads/avatar/，UUID 文件名（FileController）
21. 【代码现状】用户主页隐私开关：可隐藏历史组局（profile_privacy，V1.1）
22. 【代码现状】评价可被被评价人回复一次（reply_content）
23. 【代码现状】存在敏感词服务（SensitiveWordService，位于 service/impl 下，未抽接口）

# 4. 架构与技术栈现状

```text
frontend-h5 (Vue3+Vant4, :5173?)  ──┐
                                    ├──> backend (Spring Boot :8080, /api/**) ──> MySQL(school_buddy) + Redis
frontend-admin (Vue3+ElementPlus) ──┘
```

- 分层：controller → service/impl → mapper（MyBatis-Plus），统一返回 R + ResultCode，全局异常 GlobalExceptionHandler + BusinessException；
- 帖子状态流转有显式状态机校验器；
- VO 转换用手写 converter（PostConverter），无 MapStruct；
- 无单元测试（仅引入 starter-test 依赖，无测试代码）；
- 无消息队列、无云存储、无外部第三方服务，单体架构。

# 5. 已知问题清单（代码现状）

## 架构 / 技术栈

- A1：【代码现状】Java 8 + Spring Boot 2.7.18 —— 两者均已停止官方维护（Boot 2.x OSS 支持 2023-11 结束）；
- A2：【代码现状】Spring Security 完全 permitAll，安全全靠自定义拦截器，权限模型简单（仅 user/admin 两级）；
- A3：【代码现状】头像存本地磁盘（uploads/avatar/），多实例部署会丢失/不一致；
- A4：【代码现状】application-dev.yml 的 file.allowed-extensions 配置（gif/pdf/doc…）与 FileController 实际仅支持 jpg/png 不一致（配置未被读取）；
- A5：【代码现状】推荐接口把符合条件帖子全量载入内存打分后手动分页，数据量大时有性能风险；Redis 缓存前缀 `recommend:` 定义了但主流程未实际使用缓存。

## 代码质量

- Q1：【代码现状】ApplyServiceImpl/RecommendServiceImpl 等存在 N+1 查询（循环内逐条 selectById 查用户/帖子）；

- Q3：【代码现状】VO 字段赋值大量手写重复代码（ApplyVO/PostVO 等转换分散在 service 中）；
- Q4：【代码现状】schema.sql 表注释编号错乱（出现两个 8、两个 9），post 表 like_count 字段未见使用（待核实）。
